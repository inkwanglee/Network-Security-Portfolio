# T1110.003 - Password Spraying

## Technique Overview

**Tactic:** Credential Access  
**Technique ID:** T1110.003  
**Sub-technique of:** T1110 - Brute Force  
**Platforms:** Windows, Linux, macOS, Azure AD, Office 365, SaaS, IaaS, Google Workspace

## Description

Password spraying is a credential access technique where adversaries attempt to gain access to accounts by testing a small number of commonly used passwords against many different accounts. Unlike traditional brute force attacks that target a single account with many passwords (which triggers account lockouts), password spraying distributes authentication attempts across multiple accounts to avoid detection.

**Key Characteristics:**
- Uses common passwords (e.g., "Password123!", "Summer2024!")
- Targets multiple accounts simultaneously
- Evades account lockout policies
- Often targets management services (SSH, RDP, web applications)

## Detection Strategy

### Network-Level Detection
- Monitor authentication logs for patterns of failed login attempts across multiple accounts
- Track authentication attempts from single source IPs to multiple accounts
- Identify sequential authentication attempts with short time intervals

### SIEM Correlation Rules
```
IF failed_login_count > 5 
AND unique_target_accounts > 10 
AND time_window < 60_seconds 
AND source_ip = single_IP
THEN trigger_alert("Possible Password Spraying Attack")
```

### Snort IDS Rule
```bash
alert tcp any any -> $HOME_NET 22 (msg:"Possible SSH Brute Force Attack"; threshold:type limit, track by_src, count 5, seconds 60; sid:1000002; rev:1;)
```

**Rule Explanation:**
- Monitors TCP traffic to SSH port (22)
- Triggers when 5+ connection attempts from single source within 60 seconds
- Uses threshold limiting to prevent alert flooding

## Mitigation Strategies

### M1027 - Password Policies
**Implementation:**
- Enforce minimum 14-character passwords
- Require complexity (uppercase, lowercase, numbers, symbols)
- Prohibit common passwords and dictionary words
- Implement password history (prevent reuse of last 24 passwords)
- Regular password rotation (every 90 days for privileged accounts)

### M1032 - Multi-Factor Authentication (MFA)
**Critical Control:**
- Deploy MFA for all remote access (VPN, SSH, RDP)
- Enforce MFA for email and cloud services (Office 365, G Suite)
- Use hardware tokens or authenticator apps (avoid SMS-based MFA)
- Implement conditional access policies based on risk signals

### M1036 - Account Use Policies
**Monitoring & Response:**
- Deploy intelligent login attempt monitoring
- Implement progressive lockout (temporary lockout after 5 failures)
- Geographic anomaly detection (flag logins from unusual locations)
- Time-based access controls (restrict authentication outside business hours)
- Alert on simultaneous login attempts to multiple accounts from single IP

## SOC Playbook Response

### Alert Triage (5 minutes)
1. Review alert details: source IP, target accounts, timestamp
2. Check if source IP is internal or external
3. Verify if affected accounts are privileged/service accounts
4. Query SIEM for historical activity from source IP

### Investigation (15 minutes)
1. Correlate with other security events (IDS alerts, firewall logs)
2. Check for successful authentications following failed attempts
3. Review threat intelligence feeds for source IP reputation
4. Identify all potentially affected accounts

### Containment (Immediate)
1. Block source IP at firewall/WAF
2. Reset passwords for affected accounts
3. Force logout of any active sessions from suspicious IPs
4. Enable enhanced monitoring for affected accounts

### Remediation (24 hours)
1. Conduct password audit for targeted accounts
2. Enforce MFA on affected systems if not already enabled
3. Review and strengthen account lockout policies
4. Update detection rules based on attack patterns
