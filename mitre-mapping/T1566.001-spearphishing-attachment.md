# T1566.001 - Spearphishing Attachment

## Technique Overview

**Tactic:** Initial Access  
**Technique ID:** T1566.001  
**Sub-technique of:** T1566 - Phishing  
**Platforms:** Windows, macOS, Linux, Office 365, SaaS, Google Workspace

## Description

Spearphishing with malicious attachments is an initial access technique where adversaries send targeted emails to specific individuals, companies, or industries with malicious file attachments designed to execute malware upon user interaction. Unlike generic phishing campaigns, spearphishing involves reconnaissance and social engineering to create convincing, contextually relevant emails that motivate recipients to open attachments.

**Attack Flow:**
1. Reconnaissance: Gather target information (LinkedIn, corporate websites, social media)
2. Weaponization: Create malicious attachment (macro-enabled document, executable, PDF exploit)
3. Delivery: Send targeted email with compelling pretext
4. Exploitation: User opens attachment, executes malicious payload
5. Installation: Malware establishes persistence on victim system
6. Command & Control: Beacon to attacker infrastructure

## Common Attachment Types

### Malicious Office Documents
- **File types:** .docx, .xlsx, .pptx with embedded macros
- **Mechanism:** VBA macros execute PowerShell or download second-stage payload
- **Social engineering:** "Enable macros to view document content"

### Executables
- **File types:** .exe, .scr, .com disguised with double extensions
- **Mechanism:** Direct code execution
- **Evasion:** Icon manipulation to appear as PDF/document

### Archive Files
- **File types:** .zip, .rar with password protection
- **Purpose:** Evade email gateway scanning
- **Social engineering:** Password provided in email body

### PDF Exploits
- **Vulnerabilities:** Adobe Reader CVEs
- **Mechanism:** Embedded JavaScript, malformed objects
- **Delivery:** Appears as legitimate business document

## Detection Strategy

### Email Security Layer

**Email Gateway Controls:**
```
1. Attachment type blocking (.exe, .scr, .bat, .vbs, .js)
2. Macro-enabled Office file sandboxing
3. Sender Policy Framework (SPF) validation
4. DKIM signature verification
5. DMARC policy enforcement
```

**Suspicious Indicators:**
- Mismatched sender display name vs. email address
- External sender spoofing internal employee
- Unexpected attachments from known contacts
- Archive files with password in email body
- Urgent action requests (invoice, legal notice, HR issue)

### Endpoint Detection

**Behavior Analytics:**
- Office applications spawning cmd.exe or powershell.exe
- Unsigned executables launched from user temporary directories
- Network connections from Office processes
- Suspicious registry modifications after document open

### SIEM Correlation
```
IF email_received WITH attachment
AND (attachment_type IN blacklist OR attachment_has_macros)
AND (sender_domain NOT IN whitelist)
AND user_clicked_attachment
AND process_created IN (cmd.exe, powershell.exe, wscript.exe)
THEN trigger_alert("Possible Spearphishing Execution")
```

## Associated Threat Actors

### APT1 (Comment Crew)
- **Attribution:** China's PLA Unit 61398
- **Activity:** Large-scale spearphishing since 2006
- **Targets:** Defense, aerospace, energy, telecommunications
- **TTPs:** RAR archives with password-protected executables

### APT28 (Fancy Bear)
- **Attribution:** Russia's GRU Unit 26165
- **Notable Campaign:** 2016 US election interference
- **Delivery:** Malicious Word documents with embedded macros
- **Payload:** X-Agent, Sofacy malware families

### APT29 (Cozy Bear)
- **Attribution:** Russia's SVR
- **Campaign:** SolarWinds supply chain (initial access via other vectors, but known spearphisher)
- **Sophistication:** Custom malware, legitimate infrastructure abuse

### APT32 (OceanLotus)
- **Attribution:** Vietnam-based threat group
- **Active since:** At least 2014
- **Targets:** Southeast Asian governments, private sector, foreign organizations
- **TTPs:** Highly targeted spearphishing with custom malware

### Lazarus Group
- **Attribution:** North Korea's RGB
- **Targets:** Financial institutions, cryptocurrency, defense organizations
- **Notable:** Sony Pictures hack (2014), WannaCry connections
- **Motivation:** Financial gain, espionage, sabotage

## Malware Families Delivered via Spearphishing

### TrickBot
- **Type:** Banking trojan / modular malware platform
- **Initial delivery:** Excel spreadsheets with malicious macros
- **Capabilities:** Credential theft, network reconnaissance, Ryuk ransomware deployment
- **Evolution:** From banking trojan to ransomware-as-a-service enabler

### QakBot (Qbot, Pinkslipbot)
- **Type:** Banking trojan / malware loader
- **Delivery:** Excel or Word documents with macros
- **Persistence:** Scheduled tasks, registry Run keys
- **Payloads:** ProLock, Egregor ransomware

### Emotet
- **Type:** Modular malware loader
- **Delivery:** Word/Excel documents with malicious macros
- **Distribution:** Botnet sending phishing emails from compromised accounts
- **Secondary payloads:** TrickBot, Cobalt Strike, ransomware
- **Status:** Disrupted by law enforcement (Jan 2021) but re-emerged

### Dridex
- **Type:** Banking trojan
- **Delivery:** Office documents with embedded macros
- **Capabilities:** Credential harvesting, browser hijacking
- **Financial impact:** Millions in fraudulent wire transfers

## Mitigation Strategies

### M1017 - User Training
**Security Awareness Program:**
- Quarterly phishing simulation exercises
- Recognition of social engineering indicators:
  - Unexpected attachments from unknown senders
  - Urgent action requests creating time pressure
  - Suspicious sender addresses (typosquatting)
  - Generic greetings instead of personalized
  - Grammatical errors and awkward phrasing
- Verification procedures: Call sender via known phone number before opening attachments
- Reporting mechanisms: One-click phishing reporting button in email client

### M1049 - Antivirus/Antimalware
**Endpoint Protection:**
- Real-time scanning of email attachments
- Heuristic and behavior-based detection (not just signatures)
- Cloud-based reputation services
- Automatic quarantine of suspicious files
- Regular definition updates (daily or continuous)

### M1031 - Network Intrusion Prevention
**IPS/IDS Signatures:**
- Detection of known malware communication patterns
- C2 traffic blocking based on threat intelligence
- DNS sinkholing for known malicious domains
- SSL/TLS inspection for encrypted malware traffic

### M1054 - Software Configuration
**Attack Surface Reduction:**
```
1. Disable macros by default in Office applications
2. Block macros from internet-sourced files
3. Enable Protected View for files from internet
4. Disable external content loading in Office
5. Application whitelisting (only approved executables)
6. Disable Windows Script Host (wscript.exe, cscript.exe)
```

**Group Policy Configuration:**
```
Computer Configuration > Administrative Templates > Microsoft Office > 
Security Settings > Trust Center > Macro Settings
→ "Disable all macros except digitally signed macros"
```

### M1021 - Restrict Web-Based Content
**Email Gateway Policies:**
- Block high-risk attachment types (.exe, .scr, .bat, .vbs, .js, .jar)
- Sandbox macro-enabled documents before delivery
- Strip embedded macros from Office files
- Convert attachments to safe formats (PDF to image)
- Implement time-delayed delivery for suspicious emails

## SOC Playbook Response

### Initial Alert Handling (5 minutes)
1. **Alert details review:**
   - Email sender, recipient, subject, attachment name
   - Email gateway verdict (passed/suspicious/blocked)
   - Whether attachment was opened
   
2. **Quick triage questions:**
   - Is recipient a high-value target (executive, finance, IT admin)?
   - Was attachment opened?
   - Any unusual process activity following email receipt?

### Investigation Phase (20 minutes)

**Email analysis:**
```bash
# Extract email headers
# Check SPF, DKIM, DMARC results
# Analyze sender IP geolocation
# Review email content for social engineering tactics
```

**Attachment analysis:**
- Submit to malware sandbox (Cuckoo, Any.Run, Joe Sandbox)
- Extract file hash and search VirusTotal
- Check for known malicious IOCs
- Analyze embedded macros or scripts

**Endpoint investigation:**
```
1. Query EDR for process tree following attachment open
2. Check for suspicious child processes (cmd.exe, powershell.exe)
3. Review network connections from Office processes
4. Examine file system for suspicious writes
5. Check scheduled tasks and registry Run keys
```

### Containment (Immediate)

**If malware execution confirmed:**
1. Isolate affected endpoint from network
2. Disable compromised user account
3. Block C2 domains/IPs at firewall
4. Quarantine related emails from all inboxes
5. Reset credentials for affected user

### Eradication & Recovery (24-48 hours)

1. **Endpoint remediation:**
   - Full antimalware scan
   - Manual removal of persistence mechanisms
   - Consider full reimaging for high-severity cases
   
2. **Network-wide response:**
   - Hunt for similar emails across environment
   - Search for IOCs on all endpoints
   - Update email gateway rules
   - Add IOCs to threat intelligence platform

3. **User education:**
   - Direct coaching for affected user
   - Organization-wide security reminder if widespread campaign

### Post-Incident Activities

1. Update detection rules based on attack TTPs
2. Conduct lessons learned session
3. Improve email security controls if gaps identified
4. Document IOCs and add to threat intelligence
5. Report to relevant ISACs or threat sharing groups

## Real-World Example: Emotet Campaign Analysis

**Campaign characteristics:**
- **Delivery:** Reply-chain hijacking (emails appear as legitimate replies)
- **Attachment:** Password-protected ZIP containing Word document
- **Social engineering:** "Please review the attached document"
- **Macro behavior:** Downloads Emotet DLL from compromised WordPress sites
- **Persistence:** Creates scheduled task running every hour
- **Payload:** TrickBot → Ryuk ransomware

**Detection gap exploited:**
- Password protection bypassed email gateway sandbox
- Reply-chain made emails appear legitimate
- Time-delayed payload download evaded initial detection

**Defensive improvements:**
- Enhanced monitoring for Office processes spawning Rundll32.exe
- Behavioral detection of scheduled task creation
- Network traffic analysis for connections to compromised WordPress sites
- User training on password-protected attachments from unexpected sources

## Detection Engineering

### Splunk Query Example
```spl
index=email sourcetype=exchange
| where attachment_count > 0
| eval has_macro=if(like(attachment_extension, "%.docm%") OR like(attachment_extension, "%.xlsm%"), 1, 0)
| where has_macro=1
| eval sender_external=if(NOT like(sender_domain, "%yourcompany.com%"), 1, 0)
| where sender_external=1
| join recipient [search index=endpoint sourcetype=sysmon EventCode=1 
    (ParentImage="*WINWORD.EXE" OR ParentImage="*EXCEL.EXE")
    (Image="*cmd.exe" OR Image="*powershell.exe")]
| table _time sender recipient subject attachment_name Image CommandLine
```

### Wazuh Rule Example
```xml
<rule id="100001" level="10">
  <if_sid>400</if_sid>
  <match>powershell.exe|cmd.exe</match>
  <description>Office application spawned suspicious process</description>
  <mitre>
    <id>T1566.001</id>
  </mitre>
</rule>
```
