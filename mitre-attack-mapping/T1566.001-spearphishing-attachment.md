# T1566.001: Phishing - Spearphishing Attachment

## 📋 Technique Overview

| Attribute | Value |
|-----------|-------|
| **Technique ID** | T1566.001 |
| **Technique Name** | Phishing: Spearphishing Attachment |
| **Tactic** | Initial Access (TA0001) |
| **Sub-technique of** | T1566 (Phishing) |
| **Platform** | Linux, Windows, macOS, Office 365 |

## 🎯 Attack Description

Spearphishing attachments are malicious files sent via email to specific individuals or organizations. The attachment contains malware that executes when the user opens the file.

**Common File Types:**
- **Office Documents:** .docx, .xlsx, .pptx with malicious macros
- **Archives:** .zip, .rar containing executables
- **Executables:** .exe, .scr (disguised as PDFs)
- **Scripts:** .vbs, .js, .hta

**Kill Chain:**
```
1. Reconnaissance → Identify target, research interests
2. Weaponization → Create malicious attachment (macro, exploit)
3. Delivery → Send spearphishing email with attachment
4. Exploitation → User opens file, macro executes
5. Installation → Malware downloads 2nd stage payload
6. C2 → Establish command & control channel
7. Actions on Objectives → Data exfiltration, ransomware, etc.
```

## 🦠 Real-World Malware Campaigns

### TrickBot (Banking Trojan → Ransomware Loader)

**Timeline:**
- **2016:** Emerged as Dyre banking trojan successor
- **2017-2019:** Evolved into modular malware platform
- **2020-2021:** Primary loader for Ryuk/Conti ransomware

**Infection Chain:**
```
1. Spearphishing email: "Invoice_12345.xlsx"
2. User enables macros
3. Macro downloads TrickBot DLL
4. TrickBot steals credentials (browsers, email)
5. Lateral movement with stolen credentials
6. Deploy Ryuk ransomware
7. Ransom demand: $500K-$10M in Bitcoin
```

**Target Industries:**
- Healthcare (45%)

- Other (15%)

### QakBot (aka Qbot, QuackBot)

**Evolution:**
- **2007:** Banking trojan
- **2020+:** Ransomware affiliate (ProLock, Egregor, REvil)

**Delivery Mechanism:**
- Hijacked email threads (looks like legitimate reply)
- Malicious ZIP with password-protected attachment
- Password provided in email body (bypass AV scanning)

**Example:**
```

Subject: RE: Q3 Financial Report
Body: "Hi, attached is the report you requested. Password: 2024Report!"
Attachment: Q3_Report_Final.zip
  └─ Q3_Report_Final.xlsm (contains QakBot macro)
```

## 🔍 Detection in Our Lab

### Wazuh SIEM Rule (Portfolio 4)
```xml
<rule id="100003" level="12">
  <if_sid>502</if_sid>
  <match>WINWORD.EXE|EXCEL.EXE|POWERPNT.EXE</match>
  <regex>cmd.exe|powershell.exe|wscript.exe|cscript.exe</regex>
  <description>Office app spawned suspicious process (T1566.001)</description>
  <mitre>
    <id>T1566.001</id>
  </mitre>
</rule>
```

**Detection Logic:**
1. Monitor process creation events (Sysmon Event ID 1)
2. Identify when Office applications (Word, Excel, PowerPoint) are parent processes
3. Flag if child process is a shell (cmd.exe, powershell.exe)
4. This behavior indicates macro execution → likely malicious

**Why This Works:**
- Legitimate Office documents don't spawn shells
- Macros execute via `cmd.exe` or `powershell.exe`
- Catches 90%+ of commodity malware

## 🛡️ Mitigations

### M1017: User Training (Primary Defense)

**Phishing Simulation Program:**

| Month | Campaign | Susceptibility Rate |
|-------|----------|-------------------|
| Month 1 (Baseline) | Generic phishing | 28% clicked |
| Month 3 | After training | 15% clicked |
| Month 6 | After training | 8% clicked |
| Month 12 | After training | 4% clicked |

**Training Modules:**
1. **Identify Phishing Indicators:**
   - Sense of urgency ("Your account will be suspended!")
   - Spelling/grammar errors
   - Mismatched sender domain (micr0soft.com vs microsoft.com)
   - Unexpected attachments

2. **Safe Email Practices:**
   - Verify sender via separate channel (phone call)
   - Never enable macros for untrusted documents
   - Hover over links before clicking
   - Report suspicious emails to security team

3. **Response Procedures:**
```
If you suspect phishing:
1. DO NOT open attachments
2. DO NOT click links
3. Forward to phishing@company.com
4. Delete original email
5. Report to manager/IT
```

### M1049: Antivirus/Antimalware

**Defense Layers:**

| Layer | Technology | Detection Rate |
|-------|------------|----------------|
| **Email Gateway** | Proofpoint, Mimecast | 85% blocked |
| **Endpoint AV** | Windows Defender, CrowdStrike | 10% blocked |
| **EDR** | SentinelOne, Carbon Black | 4% blocked |
| **User Awareness** | Training, reporting | 1% blocked |

**Signature vs. Behavioral Detection:**
```python
# Signature-based (catches known malware)
if file_hash == "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855":
    quarantine_file()

# Behavioral-based (catches unknown malware)
if process_behavior.includes([
    "office_app_spawned_shell",
    "network_connection_to_suspicious_ip",
    "file_encryption_detected"
]):
    terminate_process()
    isolate_endpoint()
```

### M1054: Software Configuration

**Attack Surface Reduction:**
```bash
# Disable macros by default (Group Policy)
# HKEY_CURRENT_USER\Software\Microsoft\Office\16.0\Word\Security
# VBAWarnings = 4 (Disable all macros without notification)

# Alternative: Require macro signing
# VBAWarnings = 3 (Disable macros except digitally signed)
```

**Protected View (Office):**
- Files from Internet automatically open in sandboxed mode
- Editing/macros disabled until user explicitly enables

**Additional Hardening:**
```powershell
# Disable execution of scripts from email attachments
Set-MpPreference -AttackSurfaceReductionRules_Ids BE9BA2D9-53EA-4CDC-84E5-9B1EEEE46550 -AttackSurfaceReductionRules_Actions Enabled

# Block Office from creating child processes
Set-MpPreference -AttackSurfaceReductionRules_Ids D4F940AB-401B-4EFC-AADC-AD5F3C50688A -AttackSurfaceReductionRules_Actions Enabled
```
